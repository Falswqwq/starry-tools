# 界面与交互

整个应用就是一张画布（浅灰底，无限延伸，背景一层浅灰小点）。其余东西都浮动在它上面：

| 位置 | 是什么 |
| --- | --- |
| 左上 | **节点库**、工作流名、**说明**、**设置** |
| 右上 | **N 处问题**、加载、保存、**运行** |
| 左下 | 缩放控件 |
| 右下 | 帧率读数（灰色小字，整数 fps） |
| 底部中间 | 状态药丸，跑完点开是运行记录 |

边栏不存在 —— 按钮就是几个圆角矩形，直接排在画布上，没有外面那层胶囊壳。

右下角那个 fps 是帧间隔的指数平滑值，只在真的有帧的时候更新：空闲时画布不重绘，
读数也就停在最后一次的值（不是卡死，是没在跑）。

整帧有帧率上限（设置里可调，默认 60）：`state/pacing.rs` 在 UI 入口统一限制
**输入事件、egui 内部动画和自发重绘**，拖动也走同一限速。等待扣除已花的 UI / 渲染 /
present 时间，最多等待一帧，不忙等；不再只靠 `request_repaint_after`，也不在帧尾追加
一个完整周期。

窗口使用 `AutoNoVsync`，避免软件限帧与 FIFO vsync 叠加后从 60 掉到 30；平台不支持时由
wgpu 回退。**非 vsync 可能撕裂**，操作系统调度和实际显示仍会影响 FPS。读数是实际 UI
帧间隔的平滑估计，不是设定上限，也不是显示器扫描率；本轮尚未完成 Windows / Linux
窗口中的帧率、延迟与撕裂实测。

改名写在左上角的输入框里，说明写在它右边的按钮里，两者紧挨着；「保存」下面有一颗未保存
的小蓝点，像一条强调标注。右上角那个文件夹按钮只负责**加载**存档，不管填写。
保存 / 加载 / 删除失败时，顶部中间会弹一条提示（几秒后自己消失），不会静默失败。

「节点库」展开时，按钮上的「节点库」三个字会淡出、换成一个翻转着浮出的下箭头，
提示再点一下收回；箭头盖在原来的文字上，按钮尺寸不变。

「说明」右边那颗齿轮是**设置**，同样在它下面展开一个浮动面板：调整整帧的帧率上限
（默认 60），以及右下角那个 fps 计数器显不显示。这几个浮层
（节点库 / 说明 / 设置 / 加载）互斥，开一个就关掉其余。

这几项是「影响运行方式」而不是「工作流内容」，所以**不落进存档**，而是单独存一份
`<数据目录>/settings.json`（与 `workflows/` 分开）：启动时读回，改动后鼠标一松开就写回。

## 节点库

点「节点库」，从按钮**下面**展开一个浮动窗口：左栏是分类，右栏是工具卡片
（名称 + 一句话说明 + 输入输出类型标注）。列表长了、或者上面展开着一张卡片，就在框内滚动。

- **点一下卡片**：向上浮起展开，列出注意事项、参数说明和端口；再点别处收回。
- **按住卡片拖出去**：直接落到画布上。被拖走的那张卡片会被一个「向外」的箭头盖住，
  同时一枚显示节点名的胶囊吸附在指针上，落下时有一段入场动画。

## 右键划刀

在画布**空白处**按住右键滑动，会划出一道刀光。被刀光扫到的连线会亮成红色，表示
「将被删除」；松开右键，刀光向前跟出并消散，被切中的连线从断口向两端缩回去、断口闪
一下，然后真的从图里消失。按 Esc、或者鼠标松开在窗口外，都会取消这一刀。

判交拿的是连线上**实际渲染出来的那条贝塞尔路径**（采样成折线），不是另算一遍的近似
曲线，所以看上去碰到的就是碰到的。这部分几何在 `app/src/canvas/geometry.rs` 里，是纯函数，
有测试盯着。

右键落在节点上时不起刀 —— 那该弹节点的右键菜单（删除 / 复制）。

## 连线

从端口往外拖就能接线：一头输出、一头输入，类型对得上，Data 输入默认最多一条（变量 Set 等声明为多连的端口除外），Exec 输出最多一条；Exec 输入可有多个来源。
执行引脚与数据引脚分开判定，不能混接；Data 扇出允许多条线。
拖的过程中线会**一呼一吸地泛蓝光**表示「还没接上」；靠近一个合法端口时线会吸附过去，
线变纯蓝。松开就接上。

端点在被强调时（拉线的**起点**、它可能落下的**落点**、以及只是被**悬停**的端点）
用同一套光圈：**外圈半径始终一样**，只有「正要连上」时多一圈搏动的描边 —— 所以从
悬停到吸附再到起点，不会出现一大一小的跳变。绘制在 `canvas/render.rs`，输入处理在
`canvas/interaction.rs`，动画节奏统一来自 `ui/motion.rs`。

## 运行痕迹

**运行过程中就实时显示**：引擎**每跑完一个节点就把这个节点的完整结果**推一条进度过来
（状态 / 耗时 / 警告 / 错误 / 产物路径，连同它的**缩略图**和色板）。所以：

- 当前那个节点边框变蓝、头上写「运行中」带一个小转圈；会报进度的长任务
  （如视频压缩）还会在卡片下方的信息区长出一块：左边「帧 12/300」、右边「35% · 24 帧/s」，
  下面一条**“胶片”进度条** —— 条身里一条条细纹随进度向右流动，前沿一道细亮线（纯色细线，
  不用渐变、也没有圆点）；
- 一跑完就写上耗时，边框恢复节点专色（没有专色时用成功高亮），**结果预览随进度出现** ——
  缩略图由后台执行器生成，界面接收并缓存纹理，而不是等整张图跑完才一起显示；
- 色板（「色彩分析」）和产物操作行同理。

报告最后回来时，这些实时痕迹会被正式的运行报告接管（同一套 `apply_result`，幂等）。
开始新的一次运行、或点运行记录里的「清空」，都会先把上一次的痕迹（缩略图 / 色板 / 状态）
抹掉。

「缺东西」的节点（缺模型、或缺外部程序如 `ffmpeg`）会变警示色、挂提示并禁用参数；
缺模型时仍保留模型选择。依赖状态存在 `Node::requirements`，工具探测在后台完成并唤醒 UI，
绘制时只读快照，不同步启动子进程。模型与工具声明来自 core 的
`NodeKindInfo.model_param` / `requires_tool`。

静态检查也在后台去抖执行；改参数时先显示声明端口，检查返回后再应用真实动态类型。
检查尚未返回、或当前语义已改变时，不能用旧检查结果启动运行。

跑完之后，节点卡片右下角写一行「完成 / 出错 / 跳过 + 耗时」（绿 / 红 / 灰）。产物是小结，
排在参数区下面一块淡蓝底的小块里（信息图标 + 会折行的文字），语气是「告诉你发生了什么」
而不是「出事了」；真正出错才是红色那块。有产物时最下面还有一行「在文件夹中显示 / 另存为」。

跑过的连线会亮成主题蓝，节点仍优先使用自己声明的专色；**点一下画布空白处可收起运行高亮**，
下一次运行再亮回来。只有声明了专色的节点有专属边线（目前是逻辑类），其余走正常主题边线。

## 紫色（阻塞）节点

读取、处理、保存等节点由 Exec 触发。其中有些节点必须在运行
中途**停下来问用户**（目前只有[图像裁切](nodes/crop.md)的「形状裁切」）。这类节点的卡片
外框用**交互专色（紫）**覆盖普通边线，节点库里也挂一个紫色「交互」小标记。

有些节点只在**某些参数**下才是紫色：图像裁切切到形状模式才变紫，切回其它模式恢复普通边线。
这件事由 core 的 `NodeSpec::interactive` 回调声明，界面不识别具体节点 ID。

运行到紫色节点时：

- 底部状态药丸变成「等待「图像裁切」操作…」（紫色、呼吸的圆点）；
- 那个节点本身的紫色边框加粗一档，一眼能看出是它卡住了；
- 屏幕**中间**弹出一个**模态浮层**（背幕把画布压暗），摆出图片和遮罩，`确定` 才继续。

运行在后台线程上同步等待界面答复，然后继续当前 Exec 控制链；请求 / 答复类型见
`core/src/interaction.rs`。数据连线不会隐式运行交互节点。

## 快捷键

`Delete` / `Backspace` 删除选中节点，`Ctrl+C` / `Ctrl+V` 复制粘贴，`Ctrl+S` 保存。
焦点在输入框里时一概不抢键。

## 参数控件

节点卡片上的参数是直接改的。几种控件：

| 参数种类 | 控件 |
| --- | --- |
| 数字 | 单行输入框，带单位后缀 |
| 滑杆 | 自绘的滑杆：浅灰轨道、主题蓝已填充段、白色圆点 + 右侧读数（不是 egui 默认控件） |
| 文本 | 单行 / 多行输入框 |
| 下拉 | 自制列表盒（选项带短说明，选中的打勾） |
| 颜色 | 收起时是一条色条（透明处铺棋盘格），点开是通用取色器 |
| 开关 | 拨动开关，滑块有位移动画 |
| 文件 / 目录 | 空着是虚线框按钮，选完文件名顶在按钮的位置，鼠标移上去露出重选的按钮 |

参数可以**跟着别的参数取值**决定显不显示（core 在元数据里写 `visible_when`，支持
「或」和「而且」两种条件），例如「图像压缩」的「颜色数上限」只在
**有损 + PNG 调色板**时才出现。控件直接消费 core 的 `ParamDef` / `ParamSpec`，可见性、
默认值与参数端口不在 UI 复制。改参数后由后台检查更新动态端口类型（比如图像格式转换
选 JPEG 后，输出变成 `JPG`）。

「取色器」是一个**通用可复用**的颜色控件（core 里的 `ParamSpec::Color`）：收起时是一条
色条 —— 浅灰圆角底 + 整块圆角颜色（半透明的颜色透出底，全透明时画一道斜杠），
右上角写着 hex。点开弹出一个浮层：取色区（x = 饱和度、y = 亮度）、色相条、R/G/B 输入框、
Hex 输入框、不透明度滑杆，几者双向同步。点浮层外收起，颜色本身不改。

参数控件和卡片是**逐个节点**一起画的：控件紧贴在自己的卡片之后、又在下一张卡片之前，
所以叠在一起时上下层不会串。控件都吃掉鼠标事件，在它上面按下不会拖到节点。

## 参数端口与变量节点

能被上游喂的参数，会在参数名前多一颗**浅蓝的小圆点**和一个类型徽标（`TXT` / `NUM` /
`BOOL`）—— 这就是它的**参数端口**。小圆点的浅蓝表示「可选」；徽标的颜色只标类型，
和端口列上、节点库里的徽标**同色**（见 [配色与样式](theme.md)）。它和普通端口一样能拉
线，但画在参数那一行上，不占端口列。下拉参数没有圆点（合法值是一张固定表，不能说喂就喂）。

**浅蓝 = 可选**是个通用约定：只要一个端口不是必填（参数端口都算），它的圆点就是浅蓝；**必填**端口（不接会报错的那种）
才用主题蓝。

从**同类型**的节点接进来后，那一行的控件就变成它自己的**禁用态** —— 数字框还是数字框、
开关还是开关，只是灰下去、不再响应，而不是笼统换成一个写字的灰块。把线拔掉，控件就回来。
参数端口永远是可选的：不接就用自己的本地值。

未连接的可选参数使用本地值；已连接时必须取得合法数据，缺失或类型不匹配会失败，不回退本地值。
Data 线不调度副作用节点；变量 Get 等纯节点按需重新求值，纯数据环会报错。
运算节点本身是显式调度节点，需要 Exec 触发，成功后沿 `then` 继续。

## 变量节点

数字、文本、布尔位于节点库「变量」分类，深绿色边线。每个节点只有一个本地值参数，
以及一个 `Set` 数据输入和一个 `Get` 数据输出，没有执行引脚。

Get 可同时供多个下游读取；Set 可接多个上游，按上游实际运行的顺序以后写到的为准。
Set 不参与 Get 的求值依赖，因此 `Get → 运算 → Set` 不会成环。写入先保存在本次运行中；
成功后最终值写回节点参数，下一次运行从这里继续，失败运行不提交。详见[变量节点](variables.md)。

单节点调试仅允许纯节点和纯数据依赖，不能绕过 Exec 运行副作用节点。

控制流及迁移细节见 [Blueprint v2](engine-blueprint.md)。
