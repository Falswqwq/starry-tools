# 输入

**id** `input` · **分类** 来源 · **起点节点**（没有输入端口）

每个工作流的起点。从磁盘读入一张图像，或者直接给出文本 / 数字。一个工作流可以放多个
输入，让几条支线各走各的。新建工作流时已经带一个。

## 端口

| 方向 | 端口 | 类型 |
| --- | --- | --- |
| 输出 | `out` 值 | **动态**，跟着「类型」参数走 |

| 「类型」选的是 | 输出端口的类型 |
| --- | --- |
| 图像文件 | `Image(Png)` / `Image(Jpeg)` / … —— 按**实际文件**的格式 |
| 文本 | `Text` |
| 数字 | `Number` |

格式以**文件头**为准，扩展名只在读不出文件头时兜底。所以一个叫 `.png`、实际是 JPEG
的文件，输出的是 `Image(Jpeg)` —— 下游的类型检查照样是准的。

## 参数

| 参数 | 控件 | 默认 | 何时显示 |
| --- | --- | --- | --- |
| 类型 | 下拉 | 图像文件 | 总是 |
| 图像文件 | 文件选择 | 空 | 类型 = 图像文件 |
| 文本内容 | 多行文本 | 空 | 类型 = 文本 |
| 数值 | 数字 | 0 | 类型 = 数字 |

文件选择框过滤十种可解码的格式（PNG / JPEG / GIF / WebP / BMP / TIFF / ICO / QOI /
TGA / PNM）。选完之后节点上会显示缩略图、尺寸、格式和体积。

## 行为约定

- 选「图像文件」时输出类型跟着文件格式走 —— 选了 JPEG，输出就是 `Image(Jpeg)`。
- **工作流里只记路径，不会把图片内容一起存下来。** 文件挪走之后要重新选一次，
  真跑的时候会报「无法读取文件」。
- 还没选文件时输出 `Image(Any)`（格式未知的通配），编辑期可以接到任何图像端口上，
  运行期才要求严格对上。
- 没选文件就跑会直接失败：`还没有选择图像文件`。

## 实现

`src-tauri/src/nodes/input.rs`。

三个用 `NodeSpec::dynamic` 的节点之一（另外两个是「图像格式转换」和「图像压缩」）：
端口类型在解析工作流时由 `output_ports(params)` 现算，前端拿到的就是算好的结果。

`run` 里只做一件小事：按「类型」造一个 `Value`。图像走 `ImageValue::open`，它**只读字节、
不解码** —— 解码推迟到真有节点要看像素的时候。节点之间传递图像因此只是复制一个 `Arc`。

测试：`engine::tests::input_port_type_follows_the_selected_file`。
