# 图像格式转换

**id** `convert_image` · **分类** 图像

在常见图像格式之间转。输入收下任何能解码的格式，输出格式由「目标格式」决定 ——
**输出端口的类型跟着它变**，所以下游的类型检查仍然是准的。

## 端口

| 方向 | 端口 | 类型 |
| --- | --- | --- |
| 输入 | `image` 图像 | `Image(Any)`（必填） |
| 输出 | `image` | **动态**：`Image(<目标格式>)` |

选了 JPEG，输出端口就是 `Image(Jpeg)`；选了 PNG 就是 `Image(Png)`。这不是显示上的把戏，
产物是真的用目标格式的编码器编出来的字节，不是把标签改一改。

## 参数

| 参数 | 控件 | 默认 | 何时显示 |
| --- | --- | --- | --- |
| 目标格式 | 下拉 | PNG | 总是 |
| 画质 | 数字 1–100 % | 90 | 目标格式 = JPEG |
| 压缩档位 | 下拉 | 均衡 | 目标格式 = PNG |
| 色彩模式 | 下拉 | 保持原始 | 总是 |

- **目标格式**：PNG / JPEG / WebP / GIF / BMP / TIFF 六种能编码的格式。十种能**解码**的
  格式里，ICO 是图标容器、TGA / PNM / QOI 偏门，列在框里只是噪音。
- **压缩档位**：快速 / 均衡 / 最小体积。PNG 是无损的，这里调的只是文件大小和写盘速度。
- **色彩模式**：保持原始 / 8 位 RGB（透明区域填白）/ 8 位灰度。目标格式容纳不下的时候，
  编码器会自己挑一个能用的表示。

## 行为约定

- JPEG 存不下透明通道 —— 转过去的时候透明的地方会被压到白底上（不是直接丢掉 alpha，
  那样会留一圈黑边）。
- WebP 这里走的是**无损**编码（`image` 0.25 只提供这一种），所以没有画质可调。
- GIF 只取第一帧，动图会变成静态图；这个 crate 也不写 APNG。
- 输入已经是目标格式时会给一条提示：只是重新编码了一遍。
- 「最小体积」档写盘最慢，批量处理时先用「快速」试跑。

## 实现

`src-tauri/src/nodes/convert.rs`，用 `NodeSpec::dynamic`。

`output_ports` 从参数里读「目标格式」再拼端口；`run` 里解码 →（可选）换色彩模式 → 编码。
透传色彩模式时只复制一个 `Arc`，不复制像素。

节点 id 改过一次：原本叫 `convert_to_png`。老存档靠 `registry.rs` 里的
`LEGACY_KIND_IDS` 兜住 —— 缺的「目标格式」由默认值补成 PNG，行为和以前一样。

  且产物字节头真的是 JPEG）
