# 输入框

**id** `input_box` · **分类** 来源 · **起点节点**（没有输入端口）

一块大输入区：把文件**拖进来**、`Ctrl+V` **粘贴**，或者**点一下直接打字**。文本就显示
文本，图片就直接把图片显示出来。它是给「手边就有这段东西」准备的入口 —— 不用先去磁盘上
找个路径。

> 已经有文件路径、或者要按类型固定读法，用 [读取](read.md)。

## 端口

| 方向 | 端口 | 类型 |
| --- | --- | --- |
| 输出 | `out` 值 | **自动推断**：文本 → `Text`；图片 → `Image(<格式>)`；空着 → `Any` |

## 参数

| 控件 | 说明 |
| --- | --- |
| 输入区 | 拖入文件 / `Ctrl+V` / 点击打字 |

参数不写名字 —— 这块输入区本身就是全部内容。

## 三种状态

1. **空着** —— 一块虚线大框，中间一个加号图标，下面一行提示：能拖放的会话写
   「拖入文件 · 点击输入 · Ctrl+V」，Wayland 这类不能拖放的会话只写「点击输入 · Ctrl+V」。
   文件拖到框上时，框会亮成主题蓝、底色变浅，表示「松手就收下了」。
2. **文本** —— 里面是一个文本框，直接改就是。
3. **图片** —— 直接显示图片（棋盘格衬底，透明的像素看得见）。

有内容（文本或图片）时，框**下面会多出一个「清空」按钮**，点一下就把内容清掉、回到空框。
换一张图就是「先清空、再拖入 / 粘贴」。

因为它自己就把值摆出来了，**跑完之后卡片底下不再另摆一条结果图**（其他图像节点才会）。

## 交互约定

- **拖文件进来**：松手即装进一个输入区节点。拖放时框会亮成主题蓝。
- **`Ctrl+V`**：粘进来的如果是**一个真实存在的文件路径**，就当文件；否则当文本。
- **点击空框**：变成文本框并聚焦。没打字就点开别处 → 退回虚线框；打了字 → 留下文本。
- **清空**：框下面那个「清空」按钮把内容清掉，回到空框。
- 值存在参数 `value` 里，是一个 JSON：`""` = 空、`"一段文字"` = 文本、
  `{"file":"…"}` = 文件。工作流只记路径，不把图片内容存下来。

### 拖放 / 粘贴交给哪个框

**不能按指针位置挑**：系统在拖放过程中根本不上报光标位置 —— winit 的 X11 后端收到
`XdndPosition` 也不转成光标事件，**Wayland 后端干脆没有文件拖放**。所以顺序是：
（如果恰好有）光标落在哪个框 → **选中的**那个 → 唯一的那个。想指定目标，先点一下那个
节点。

> **Wayland 上没有拖放**：winit 0.30 的 Wayland 后端不实现文件拖放，所以拖文件不会
> 有反应，空框的提示也会相应只写「点击输入 · Ctrl+V」。改用 `Ctrl+V`（文件管理器复制
> 会把路径放进剪贴板），或者先点进去打字。想在 Wayland 会话里用拖放，可以跑在
> XWayland 上：`env -u WAYLAND_DISPLAY ./starrytools`。

## 实现

`core/src/nodes/input_box.rs`（读值、推断输出类型、`run`）+ 前端的
`Graph::draw_drop_zone`（`app/src/graph.rs`，整块输入区的画法与交互）。

控件的种类是 `ParamSpec::DropZone`（core）→ `Control::DropZone`（app）；前端按
**控件的种类**分派到自定义画法，而不是认节点 id —— 所以「界面不认识任何具体工具」
这条规矩还成立。

测试：`engine::tests::input_box_runs_its_typed_text_and_infers_the_type`、
`engine::tests::input_box_with_an_image_file_infers_the_format`、
`engine::tests::rename_passes_a_non_image_value_through_untouched`（文本透传）。
