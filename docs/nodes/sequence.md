# 顺序执行

**id** `sequence` · **分类** 逻辑

给本来彼此独立的分支排一个先后。它的输出是一排**空信号**，接到哪个分支上，那个分支就归到
这个序号下；运行到它时，各个分支按输出的**从上到下**的顺序依次执行。

它不需要任何数据输入 —— 因此自动带一个「空输入」（`-`），本身也能挂到别的逻辑输出上。

## 端口

| 方向 | 端口 | 类型 |
| --- | --- | --- |
| 输入 | `seq` 空输入 | `-`（`VOID`，可空着） |
| 输出 | `out1` 执行 | `-`（`VOID`，**必须**） |
| 输出 | `out2` … `outN` | `-`（`VOID`，可选） |

每个输出都是一个空信号，**不传数据**。把「[读取](../nodes/read.md)」「[保存到目录](../nodes/save.md)」
这类不需要数据输入的节点接到它们各自的空输入上，这些节点的执行顺序就由这里的序号说了算。

输出端口**直接画在参数栏里** —— 「输出」那个控件每一行的右端各一个（顶部端口列里
只剩那一个空输入）。这是输出端口的一种画法：`PortDef::panel_row` 说「这个输出挂在参数栏第几行」。

## 参数

| 参数 | 控件 | 默认 | 说明 |
| --- | --- | --- | --- |
| 输出 | 动态输出 | 1 | 一列带序号的输出；按底部加号增加一个，按每行的叉删掉一个。第一个是必须的，删不掉。每行左边还有一个**阻塞开关**。 |

输出版口是**动态**的：`out1`（必须）+ `out2` … `outN`（可选），id 由 `out` 加序号拼成。

### 阻塞 / 非阻塞

每一行都有一个开关（上面标着「阻塞」，存在参数 `block{序号}` 里，缺省是**开**）：

- **开（阻塞）**：这一段跑完之后，后面的输出才轮到。这是「顺序执行」本来的意思。
- **关（非阻塞）**：这一段**不施加任何先后约束**，它和其余非阻塞段之间就按拓扑序随便排。

于是同一个节点能同时做「先干 A（阻塞），再让 B / C 一起跑」。

## 行为约定

- 序号小的分支**先跑**；挂在**同一个**输出上的几个分支之间不再分先后。
- 排序是引擎在排拓扑序时加的约束（`engine::sequence_ordering`）：只有当前一个输出**开着**
  阻塞开关时，才把第 k 个输出的直接下游排到第 k+1 个的直接下游之前。关掉就不加这条边。
- 如果排出来的先后和别的连线要求**矛盾**（比如 out1 的分支又依赖 out2 的分支），
  会报一个「循环」的错。
- 「顺序执行」可以嵌套：只要外层的每个输出各接一个内层（或别的节点），先后就一层层叠起来。

## 例子

```
读取 ─ 图像 ─┬─→ 保存到目录 A
              └─→ 保存到目录 B

顺序执行 ─ out1 ─(空输入)─→ 保存到目录 A
         └ out2 ─(空输入)─→ 保存到目录 B
```

两个「保存到目录」本来谁先谁后都行；把它们的空输入分别接到 out1 / out2 上之后，
就一定先写 A、再写 B。
