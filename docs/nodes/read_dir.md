# 读取目录

**id** `read_dir` · **分类** 来源

把一个目录里的文件读成一个**列表**：图像装成 `List[Img]`，文本装成 `List[Text]`。
它是第一个产出列表的节点，和「[遍历](iterate.md)」正好配上 —— 读一个装满图的目录，
交给「遍历」一项项解包处理。

和「[读取](read.md)」一样是**起点**节点（因此自动带一个「空输入」，可以挂到逻辑输出上排先后）。
工作流里只记目录路径，不存文件内容 —— 目录变了重新跑就行。

## 端口

| 方向 | 端口 | 类型 |
| --- | --- | --- |
| 输入 | `seq` 空输入 | `-`（`VOID`，可空着） |
| 输出 | `out` 列表 | `List[Img]` 或 `List[Text]`（跟着「类型」参数） |

## 参数

| 参数 | 控件 | 默认 | 说明 |
| --- | --- | --- | --- |
| 类型 | 下拉 | 图像文件 | 图像文件装成 `List[Img]`；文本文件装成 `List[Text]` |
| 目录 | 目录选择 | 空 | 要读的目录 |
| 包含子目录 | 开关 | 关 | 打开时连子目录里的文件一起读 |

## 行为约定

- 文件按**文件名的字典序**排，所以列表顺序是稳定的。
- 不是目标类型的文件直接跳过：图像模式只收能识别的图像扩展名；文本模式只收常见文本扩展名。
- 单个文件读不出来（损坏、编码不对）就跳过它，最后报一句跳过了几个。
- 一次最多读 **1024** 个，多了会截断并提示 —— 免得指到一个大目录把内存吃光。
- 目录里一个可读文件都没有时，直接报错，而不是交出一个空列表（空列表接不进
  `List[Img]` 那种具体端口）。
- 混合格式的图像目录，输出的元素类型收窄成「图像」接口 —— 也就是 `List[Img]`，
  而不是笼统的 `List[Any]`。

## 例子

```
读取目录（图像）─ List[Img] ─→ 遍历 ─ elem1 ─→ 缩放图像
                                    ├ elem2 ─→ 缩放图像
                                    └ finally ─→ 保存到目录
```

目录里前两张图各走一次「缩放图像」（分别接到 `elem1` / `elem2`），两张都送完之后，
「结束」触发收尾那一步。
