# 遍历

**id** `iterate` · **分类** 逻辑

对列表里的**每个元素**把下游那一支跑一遍。接在「元素」输出后面的整段子图会**逐个元素
执行一次**，当前元素从「元素」这个输出喂进去。结构像：

```text
for item in list {
    下游那一支（「元素」输出就是当前这个）
}
finally { … }
```

另有可选的「结束」输出 —— 所有元素跑完才发出一个空信号，用来接收尾的节点。

## 端口

| 方向 | 端口 | 类型 |
| --- | --- | --- |
| 输入 | `list` 列表 | `List[Any]`（必填，任意列表都行） |
| 输出 | `item` 元素 | `ANY`（当前这个元素，**必填**） |
| 输出 | `finally` 结束 | `-`（`VOID`，可选） |

「元素」是 `ANY` —— 编译期不知道列表里装的是什么，运行期再接下游的严格校验核对。
只有一个（循环体）输出：**同一个操作套在每个元素上**，不需要给每个元素各配一个输出。
它标为**必填**（必接的那一端）：不接就等于循环体什么都不做，画布上会提示。

「结束」是可选的：不接也没关系，但它一直在、删不掉。

## 参数

| 参数 | 控件 | 默认 | 说明 |
| --- | --- | --- | --- |
| 最大遍历数目 | 数字 | 0 | 最多跑多少个元素；**0 表示不限制**（把列表跑完为止） |

## 行为约定

- 接在「元素」下游的**整段子图**按元素逐个跑一遍；当前元素就是那一刻的「元素」输出。
- 「最大遍历数目」是 0 时跑完整条列表；大于 0 时最多跑这么多个（列表更短就跑列表那个数）。
- 循环体的**外部**依赖一定会先算好再进循环（引擎在排拓扑序时加了这条约束）。
- 循环体里某个节点每轮的产物，自动输出目录里会带上轮次前缀（`001-…`、`002-…`），
  不会互相盖掉。**嵌套**时是整个轮次路径（`001-002-…`）。
- 报告里循环体的节点只出现**一条**：耗时累加、警告合并、状态取最重的那个（出错 > 跳过 > 完成）。
- 列表为空时循环体不跑，节点报「跳过」。
- **可以嵌套**：循环体里再放一个遍历也成立 —— 内层对每个外层元素各跑一遗。

## 例子

```
读取目录（图像）─ List[Img] ─→ 遍历 ─ item ─→ 缩放图像
                                  └ finally ─→ 保存到目录（收尾）
```

目录里每张图都走一次「缩放图像」，全部跑完之后，「结束」触发收尾那一步。
