# 配色与样式

黑 / 白 / 灰承载内容，蓝（`ACCENT = #2563eb`）表示主要操作、焦点和运行信号。
**类型色、节点专色和错误 / 警示色各有职责**，不是全屏只准一种蓝。

## 主题与字体

令牌集中在 `app/src/ui/theme/`：

- `colors.rs`：表面、文字、强调、状态、透明度；类型色与节点专色只从 core 注册表转换。
- `metrics.rs`：圆角、间距、阴影等尺寸。
- `fonts.rs`：字号与系统字体候选。Windows 从 `WINDIR` / `SystemRoot` 的 `Fonts` 找
  微软雅黑 / 黑体 / 宋体及 Cascadia Mono / Consolas；Linux 保留 Noto Sans CJK、Droid、
  JetBrains / DejaVu Mono 候选。缺候选时回退内置字体，不保证有中文字形。

节点卡片、节点库、各种浮层共用**白底、发丝边、圆角、阴影**。不要在每个组件里复制颜色或尺寸。

## 类型颜色

徽标只回答「这个端口是什么类型」，与节点状态无关：

| 类型 | 注册颜色 |
| --- | --- |
| 图像（接口与具体格式） | 蓝，独立于选中态 `ACCENT` |
| 视频（启用 video） | 青 |
| 文本 / 数字 / 布尔 | 各自的灰阶 |
| 通配 / 文件 / 空信号 | 中性灰 |

端口列、参数前、节点库都调用 `theme::badge_color(ty)`。`TypeColor` 是 core 的
`[u8; 3]` RGB 值；`theme::type_color` 只是转成 `Color32`，不是封闭枚举映射。
扩展注册类型时直接贡献颜色，无须 UI 增加分支。具体格式由徽标文字说清，不靠颜色猜。

## 节点专色与状态

专色说的是「**这类节点**长这样」，与节点库分类**无关** —— 分类只把节点分组，名字不带颜色。
颜色册由 `RegistryBuilder::register_accent(id, color)` 注册，节点用 `NodeSpec::accent(id)`
声明自己属于哪一类；界面按 id 取色（`theme::accent_color`），不认识具体节点。

| 专色 id | 谁声明 | 颜色 |
| --- | --- | --- |
| `logic` | 顺序执行 / 遍历 | 暗蓝 `#1e40af` |
| `data` | 文本 / 数字 / 布尔（变量节点） | 深绿 `#166534` |
| `interactive`（保留） | 框架：当前会拦住运行的节点 | 紫 `#7c3aed` |

`interactive` 不由节点静态声明 —— 同一个节点（如「图像裁切」）换个参数才变成紫色，
所以由 `NodeSpec::interactive` 回调推导，界面取同一个 id 的颜色。
节点边线优先级为错误红、运行蓝、缺依赖警示色、专色（交互优先于节点声明）、
成功高亮、普通边线；状态消失后回到原本的边线。

需要新增一种**带专色的节点类**时，注册一个专色 id 并在节点上声明即可 ——
组件的着色逻辑不用改。`PURPLE_SOFT` / `PURPLE_LINE` 是交互专色派生的浅色底 / 描边，
只用于卡片上的「交互」小标记。等待时边线加粗，状态药丸也有文字提示。

分类不参与节点外观：把分类色当成节点色，会让节点按分组被染成一片。

## 组件与动画

`ui/widgets/` 包含按钮与浮层外壳，`ui/widgets/controls.rs` 负责数字、文本、下拉、开关、
文件和颜色控件。它们按统一令牌自绘，不靠 egui 默认皮肤决定节点外观。
`ui/panels/` 放 chrome、library、prompt、report；`ui/icons/` 将 vendored 的
`app/assets/icons/` SVG 光栅化并缓存，`svgpath.rs` 负责路径解析。

时长、缓动和节奏统一放在 `ui/motion.rs`：面板进出场、卡片展开、开关、待连接呼吸、spinner、
入场与断线动画都共享令牌和函数，不在各处维护另一套 easing / speed 常量。
帧率由 `state/pacing.rs` 统一调度，动画不能通过另开重绘时钟绕过整帧限制。

几个实现约束：

- **开放路径描边而不填充**，避免断线曲线与弦之间出现黑块。
- **开关滑块逐帧位移**，而非两个静止状态切换。
- 文字按**墨迹**居中（`widgets::ink_top`），避免汉字与拉丁字母视觉错位。
- 透明色使用同一 alpha 转换，保留 `Color32` 的预乘通道，避免阴影越乘越黑。

单测覆盖令牌、缓动和颜色转换，不代表窗口观感已经验证。Windows / Linux 的中文、动画节奏、
真实帧率与非 vsync 撕裂仍需本地起窗口验收，见[界面](interface.md)与[开发](development.md#性能与界面验收)。
