# 配色与样式

内容只用黑 / 白 / 灰，蓝（`#2563eb`）是唯一的主题色：主要操作用它，选中态用它，
运行时的信号流光也用它。字体只自带一款 JetBrains Mono（拉丁与数字，等宽，数字能对齐），
中文走系统回退（Noto Sans CJK）。

所有 token 都在 `app/src/theme.rs` 一处 —— 换配色只改那里，不用翻每个组件。

## 同一套表面

节点卡片、节点库、各种浮层共用同一套表面：**白底、发丝边、同一个圆角、同一个阴影**，
所以整屏看起来是一件东西。

## 类型颜色

类型颜色也收在蓝灰这条梯度上：

| 类型 | 颜色 |
| --- | --- |
| 具体格式的图像 | 蓝（`TYPE_IMAGE`，与主题蓝分开） |
| 格式未知的图像 / `Any` | 灰 |
| 文本 / 数字 / 布尔 | 灰 |

徽标的颜色**只管一件事：这个端口是什么类型**。端口列上的徽标、参数名前的徽标、
节点库卡片与详情里的徽标，全部走同一个函数 `theme::badge_color(ty)` —— 因此**同一
类型的徽标在哪儿都同色**。它不看节点、不看状态（选中 / 悬停 / 报错是别的颜色在管），
也特意不复用主题蓝 `ACCENT`（那个蓝表示选中 / 焦点），免得一个蓝色徽标被误读成“选中”。

「到底是 PNG 还是 JPG」由徽标上的**字**说，不靠颜色猜 —— 十种格式各占一个色相，在
这么小的徽标上也分不出来。类型本身在 `core/src/model/port_type.rs`。

紫色（`PURPLE`）是**节点种类**的颜色，不是状态色：只有[阻塞节点](interface.md#紫色阻塞节点)
（要你动手的）的卡片外框用它，运行时那个正在等你的节点会把紫边框加粗一档。
紫色的深浅还有两个变体（`PURPLE_SOFT` 底、`PURPLE_LINE` 边），只给节点库里那个
「交互」小标记用。

## 组件层

按钮、下拉、开关、输入框这些外壳都是**自己画的**（`app/src/widgets.rs` 与
`app/src/graph.rs`），不套 egui 默认控件的外观：

- 原因是节点那层（纸片卡片、端口、连线）本来就不该由控件库决定，外壳跟着同一套 token
  画出来，风格才统一。
- egui 的默认按钮给不出「实心 / 幽灵 / 主色 / 危险」这几种变体，也给不了每个按钮自己的
  卡片阴影，所以干脆铺开自己画。

有几个坑值得记一笔，它们都只在屏幕上看得出来：

- **开放路径要描边、不要填充。** 连线和断开动画里那两条自己画的贝塞尔，一旦被当成闭合
  形状填色，曲线和弦围出来的那块会变成实心——「曲线被切断时周围变黑」就是这么来的。
- **开关的圆点要真的动。** 只画两个静止状态是不够的，得有一帧一帧的位移，否则看着像没动画。
- **按「墨迹」而不是「行高」做竖直居中。** 汉字的墨迹在行框里偏下、拉丁大写偏上，
  两者各自按框高居中就会显得错位（`widgets::ink_top` 处理这个）。

这些都在 `app/src` 的单测和本地跑起来时的观感里盯着（egui 的界面没法像 DOM 那样做快照测试）。
