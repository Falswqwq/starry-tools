# 端口类型系统

端口上带着类型，连线时就会检查。实现在 `core/src/types/`。

类型分两层：

- **接口（trait）** —— 一族类型的共同身份，本身**不是一个类型**，而是「哪些类型算一类」。
  像 `IMG`（图像）、`VID`（视频）、`FILE`（能写盘的产物）、`ANY`（通配）。
- **具体类型** —— `PNG` / `JPEG` / `TEXT` / `MP4`…… 每个具体类型声明它实现哪些接口。

**没有派生 / 继承，只有「实现接口」。** `IMG` 想说自己也能当 `FILE` 用，只是把自己的
`traits` 里写上 `"file"` 而已；`PNG` 和 `JPEG` 是并列的两种具体类型。

```
ANY        通配接口（一切类型都实现它）
FILE       能写盘的产物接口
  IMG      图像接口（实现 FILE）
    PNG / JPEG / GIF / WEBP / BMP / TIFF / ICO / QOI / TGA / PNM
  VID      视频接口（实现 FILE，启用视频功能时才有）
    MP4 / MKV / WEBM / MOV / AVI
TEXT       文本
NUMBER     数字
BOOL       布尔
```

一个端口（[`PortType`]）要么指向一个**具体类型**（只收它自己），要么指向一个**接口**
（收下所有实现它的类型）。所以「图像格式转换」的输入是 `IMG`（什么图像都能接），
「缩放图像」的输入是 `PNG`（只收 PNG），「保存到目录」的输入是 `FILE`（图像、视频都行）。

## 三条规则

- **具体类型只接同一种。** `PNG` 端口接不下 `JPEG` —— 得先经过「图像格式转换」。
- **接口收下所有实现它的类型。** `FILE` 收 `PNG`，也收 `MP4`；`IMG` 只收图像。
- **「说不清」在编辑期放行，运行期不放行。** `ANY` 两头出现就放行；一个还没定格式的
  输出（`IMG`）接到了具体端口上，编辑期也先放行，等真跑起来实际格式必须严格对得上。

`accepts()` 是编辑期的规则（宽松），`strictly_accepts()` 是运行期的规则（严格）。

## 徽标颜色只看类型

同一类型的徽标在哪儿都同色 —— 颜色只回答「这是什么类型」，与节点的选中 / 运行 / 报错
状态无关，也不借用主题蓝（那个蓝表示选中）。颜色是按**语义色令牌**（`TypeColor`）分的，
具体的一处映射在 `app/src/ui/theme.rs`：图像类一种、视频类一种、文本 / 数字 / 布尔各一种、
通配一种。新增一类类型时，令牌加一个、颜色映射加一条，别在别处塞硬编码颜色。

## 加一种类型（feature）

其它 feature（视频、以后可能的音频……）用 `Registry::register_trait` /
`register_type` 在启动时把自己的接口与类型补进登记表，界面侧完全不用改 —— 它只认登记表。
视频模块就是这么做的，见 `core/src/features/video/mod.rs` 的 `register()`。

## 色板就是文本

「色板」不单列一种类型 —— 它就是 `TEXT`，约定每行一个 `#rrggbb`。所以「色彩分析」
输出的色板能直接接给任何 `TEXT` 端口，也能接给「颜色」参数。一个节点只要一种颜色、
却拿到一整板多色的，就取第一种颜色。

引擎在打包运行报告时会用 `model::value::parse_palette` 认出这种文本，把颜色拆到
`PortResult.palette` 里，界面据此在卡片上画一排小色块。

## 两趟检查，都在 Rust 里

| 时机 | 做什么 |
| --- | --- |
| 每次改动图 | `resolve` 静态检查：画出每个端口的真实类型、判连线合不合法、标红 |
| 执行时 | 再核一遍上游实际产出的值的类型 |

**界面不自己推算类型**，只渲染 core 在元数据里给的 `PortDef.ty`。拖连线时为了能**同步**
判断，`app/src/canvas/graph.rs` 的 `can_link` 直接调 `PortType::accepts`（和静态检查同一套规则），
但静态检查每次都会重新跑一遍，以那边为准。

## 端口类型是「动态」的节点

大多数节点的端口类型写死在元数据里；下面这几个是现算的，用 `NodeSpec::dynamic(kind,
resolve_outputs, run)`：

| 节点 | 端口跟着什么变 |
| --- | --- |
| [读取](nodes/read.md) | 「类型」参数，图像还要跟着所选文件的真实格式（没选文件时是 `ANY`） |
| [图像格式转换](nodes/convert.md) | 「目标格式」参数 |
| [图像压缩](nodes/compress.md) | 「压缩方式」（有损 + JPEG 时才出 `JPEG`） |
| [视频压缩](nodes/video_compress.md) | 「输出格式」参数 |

节点库里展示的卡片是个**模板**：端口画的是**声明里的样子**（静态的），不是某个参数
组合下算出来的样子。所以动态输出的节点在卡片上显示泛化的类型 ——「读取」是 `ANY`、
「图像格式转换」/「图像压缩」是 `IMG`、「视频压缩」是 `VID`；拖出来、定下参数后，
端口才变成具体的 `PNG` / `JPG` / `MP4` 之类。（实现在 `core/src/registry.rs` 的 `kinds()`。）

## 参数端口：让参数也能被上游喂

除了「输入端口」，每个**能被上游喂**的参数会**自动**多出一个**参数端口**
（id 是 `param:<参数 id>`，比如 `param:percent`）。推导规则只有一条
（`ParamSpec::input_type`）：

| 参数控件 | 能不能有端口 | 端口类型 |
| --- | --- | --- |
| 数字 / 滑块 | 能 | `NUMBER` |
| 文本 | 能 | `TEXT` |
| 开关 | 能 | `BOOL` |
| 文件选择 | 能 | `TEXT`（路径也是字符串） |
| 下拉 | **不能** | —— |

下拉为什么不能：它的合法值是一张固定表（“邻近 / 线性 / Lanczos3”），不是任意值，
让上游乱喂进来的话运行期就得再把关一次，得不偿失。起点节点（注册表里的字面量、
以及没有输入的节点）也不生成参数端口 —— 它自己就是喂参数的那一端。

参数端口是**推导**出来的（`NodeKind::inputs_for`），因此：

- 它天然参与**连线合法性检查**和**运行期严格校验**，没有额外的代码；
- 收到 `param:<id>` 的边时，引擎把值**覆盖到那个参数上**，不当作节点的输入数据；
- 参数一改，界面调 `refresh_ports` 重算，端口跟着变。

## 通用产物值

图像有专门的 `ImageValue`（带解码缓存、能出预览）。视频这类产物只需要「类型 + 编码后的
字节 + 一点元信息」，用 `core/src/media.rs` 的 `MediaValue`，类型用登记表里的具体类型 id
表示，写盘扩展名也从登记表取 —— 加一种新格式不用改它。「保存到目录」接受 `FILE` 接口，
两种产物都写得下去。
