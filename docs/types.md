# 端口类型系统

端口上带着类型，连线时就会检查。实现在 `core/src/model/port_type.rs`。

```
Any          任意值（通配，什么都不挑）
Text         文本
Number       数字
Bool         布尔
Image(Png)   PNG 图像
Image(Jpeg)  JPEG 图像
Image(Any)   格式未知的图像（通配）
…            还有 GIF / WebP / BMP / TIFF / ICO / QOI / TGA / PNM
```

## 三条规则

- **`Image(Png)` 和 `Image(Jpeg)` 是两种不同的类型。** 把 JPEG 直接接到「缩放图像」上
  会被拒绝 —— 得先经过「图像格式转换」，把目标格式选成 PNG。
- **「格式未知」在编辑期放行，运行期不放行。** 「图像格式转换」这类节点的输入声明为
  `Image(Any)`，什么图像都能接；等真跑起来，实际的格式必须严格对得上。
- **`Any` 是给通用节点用的通配。** 「重命名」这种不管值的类型的节点，输入输出都声明成
  `Any`；「输入」节点还没选文件时输出也是 `Any`（类型待定）—— 编辑期什么都能接进来、
  接出去，运行期再要求实际值是个说得清的类型。

`accepts()` 是编辑期的规则（宽松），`strictly_accepts()` 是运行期的规则（严格）。
两者的差别只有上面那两条通配规则。

## 色板就是文本

「色板」不单列一种类型 —— 它就是 `Text`，约定每行一个 `#rrggbb`。所以「色彩分析」
输出的色板能直接接给任何 `Text` 端口，也能接给「颜色」参数（它的输入端口是 `Text`）。
一个节点只要一种颜色、却拿到一整板多色的，就取第一种颜色。

引擎在打包运行报告时会用 `model::value::parse_palette` 认出这种文本，把颜色拆到
`PortResult.palette` 里，界面据此在卡片上画一排小色块。

## 两趟检查，都在 Rust 里

| 时机 | 做什么 |
| --- | --- |
| 每次改动图 | `resolve_workflow` 静态检查：画出每个端口的真实类型、判连线合不合法、标红 |
| 执行时 | 再核一遍上游实际产出的值的类型 |

**界面不自己推算类型**，只渲染 core 在元数据里给的 `PortDef.ty`。拖连线时为了能**同步**
判断，`app/src/graph.rs` 的 `can_link` 直接调 `PortType::accepts`（和静态检查同一套规则），
但静态检查每次都会重新跑一遍，以那边为准。

## 端口类型是「动态」的节点

大多数节点的端口类型写死在元数据里；下面这几个是现算的，用 `NodeSpec::dynamic(kind,
resolve_outputs, run)`：

| 节点 | 端口跟着什么变 |
| --- | --- |
| [读取](nodes/read.md) | 「类型」参数，图像还要跟着所选文件的真实格式（没选文件时是 `Any`） |
| [输入框](nodes/input_box.md) | 里面装的是文本、图片，还是空着 |
| [图像格式转换](nodes/convert.md) | 「目标格式」参数 |
| [图像压缩](nodes/compress.md) | 「压缩方式」（有损 + JPEG 时才出 `Image(Jpeg)`） |

节点库里展示的卡片是个**模板**：端口画的是**声明里的样子**（静态的），不是某个参数
组合下算出来的样子。所以动态输出的节点在卡片上显示泛化的类型 ——「读取」/「输入框」是
`ANY`、「图像格式转换」/「图像压缩」是 `IMG`；拖出来、定下参数后，端口才变成具体的
`PNG` / `JPG` 之类。（实现在 `core/src/registry.rs` 的 `kinds()`。）

## 参数端口：让参数也能被上游喂

除了「输入端口」，每个**能被上游喂**的参数会**自动**多出一个**参数端口**
（id 是 `param:<参数 id>`，比如 `param:percent`）。推导规则只有一条
（`ParamSpec::input_type`）：

| 参数控件 | 能不能有端口 | 端口类型 |
| --- | --- | --- |
| 数字 / 滑块 | 能 | `Number` |
| 文本 | 能 | `Text` |
| 开关 | 能 | `Bool` |
| 文件选择 | 能 | `Text`（路径也是字符串） |
| 下拉 | **不能** | —— |

下拉为什么不能：它的合法值是一张固定表（“邻近 / 线性 / Lanczos3”），不是任意值，
让上游乱喂进来的话运行期就得再把关一次，得不偿失。起点节点（注册表里的字面量、
以及没有输入的节点）也不生成参数端口 —— 它自己就是喂参数的那一端。

参数端口是**推导**出来的（`NodeKind::inputs_for`），因此：

- 它天然参与**连线合法性检查**和**运行期严格校验**，没有额外的代码；
- 收到 `param:<id>` 的边时，引擎把值**覆盖到那个参数上**，不当作节点的输入数据；
- 参数一改，界面调 `refresh_ports` 重算，端口跟着变。
