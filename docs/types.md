# 端口类型系统

端口上带着类型，连线时就会检查。实现在 `src-tauri/src/model/port_type.rs`。

```
Any          任意值（通配，什么都不挑）
Text         文本
Number       数字
Bool         布尔
Image(Png)   PNG 图像
Image(Jpeg)  JPEG 图像
Image(Any)   格式未知的图像（通配）
…            还有 GIF / WebP / BMP / TIFF / ICO / QOI / TGA / PNM
```

## 三条规则

- **`Image(Png)` 和 `Image(Jpeg)` 是两种不同的类型。** 把 JPEG 直接接到「缩放图像」上
  会被拒绝 —— 得先经过「图像格式转换」，把目标格式选成 PNG。
- **「格式未知」在编辑期放行，运行期不放行。** 输入节点还没选文件时输出 `Image(Any)`，
  它可以接到任何图像端口上；等真跑起来，实际的格式必须严格对得上。
- **`Any` 是给通用节点用的通配。** 「重命名」这种不管值的类型的节点，输入输出都声明成
  `Any`：编辑期什么都能接进来、接出去，运行期再要求实际值是个说得清的类型。

`accepts()` 是编辑期的规则（宽松），`strictly_accepts()` 是运行期的规则（严格）。
两者的差别只有上面那两条通配规则。

## 两趟检查，都在 Rust 里

| 时机 | 做什么 |
| --- | --- |
| 每次改动图 | `resolve_workflow` 静态检查：画出每个端口的真实类型、判连线合不合法、标红 |
| 执行时 | 再核一遍上游实际产出的值的类型 |

**前端不自己推算类型**，只渲染后端在元数据里给的 `PortDef.ty`。前端确实有一份
`accepts` 的镜像（`src/lib/ports.ts`），但那只是为了拖连线时能**同步**判断，后端每次都会
重新检查一遍，以那边为准。

## 端口类型是「动态」的节点

大多数节点的端口类型写死在元数据里；有三个是现算的，用 `NodeSpec::dynamic(kind,
resolve_outputs, run)`：

| 节点 | 端口跟着什么变 |
| --- | --- |
| [输入](nodes/input.md) | 「类型」参数，图像还要跟着所选文件的实际格式 |
| [图像格式转换](nodes/convert.md) | 「目标格式」参数 |
| [图像压缩](nodes/compress.md) | 「压缩方式」（有损 + JPEG 时才出 `Image(Jpeg)`） |

节点库里展示的卡片用的是**默认参数**下的样子，所以卡片上写的 `IMG → PNG` 和真拖出来
那个节点的初始状态一致。
